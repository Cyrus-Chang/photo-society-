# 撮合 Agent 追问与可解释规划设计

## 意图
把现有撮合 Agent 从“能跑”提升到可追问、可核对、可评测：规则规划继续保证无 key 可用，LLM 只在可选配置下输出受限的工具计划；槽位覆盖真实口语；缺关键条件时先追问；工具结果和候选排序都保留证据。

## 目标
- `run_agent` 返回 `planner: "llm" | "rule"`、规划耗时/成功率信息和完整 `toolTrace`。
- 解析相对时间、预算区间、模糊风格、人数与主题，并保持原有城市/预算/风格兼容。
- 缺城市或预算时不硬猜，返回 `missingFields` 与反问句。
- 增加 `estimate_price`（仅引用公开集市需求预算，带来源；无数据明确写“需向对方确认”）和 `check_slot`（按日期筛选）。
- 前端展示候选对比、开场话术、沟通要点、追问和 planner/延迟。
- 评测至少 30 条，输出槽位/安全/同城/规划成功率及 P50/P95，落盘 JSON。

## 非目标与约束
- 不编造价格、档期、经历；所有缺失数据都显式标注需确认。
- 不新增第三方依赖；LLM 通过标准库 `urllib` 调 OpenAI 兼容接口。
- 仅修改允许的前端文件，以及 Agent 后端和评测脚本。
- 无 LLM key 时必须可运行，并明确记录“LLM 规划器在无 key 时不可验证”。

## 方案
1. **纯规则扩展**：改动最小，但无法验证 LLM 计划链路，也无法记录两种模式差异。
2. **LLM 全权编排**：灵活但不可控，容易越权调用工具或违反 C2。
3. **受限 LLM 规划 + 规则兜底（采用）**：LLM 只能返回白名单工具名和参数；解析失败、无 key、超时或工具失败自动使用规则计划，执行层统一校验和记录。

## 结构
- 解析层：规则提取规范化槽位（城市、预算 min/max、时间窗口、风格、人数、主题）。
- 规划层：`plan_with_llm` 输出 JSON 步骤；`build_rule_plan` 生成同等结构；`validate_plan` 做白名单与参数约束。
- 工具层：`search_works`、`check_availability`、`check_slot`、`estimate_price`；每步写入 `toolTrace`。
- 结果层：按同城优先排序，候选附可约时间、标签重合、向量分、价格参考来源、沟通要点；缺关键槽位提前返回。
- 评测层：固定 30+ 条标注，分别统计 rule/llm（无 key 时记录不可验证）、准确率和 P50/P95。

## 验收
- `vue-tsc -b` 退出码 0。
- `tools/eval_agent.py` 可复跑，`.review-tmp/agent-eval.json` 含 30+ 条明细与 summary。
- `/match` 在无头 Edge 可点击并返回结果；记录截图或 CDP 日志。
