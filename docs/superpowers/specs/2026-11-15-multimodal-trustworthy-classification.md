# 拍社多模态识别可信化设计

## 目标

上传图片后，系统要让用户知道哪些标签来自 AI、哪些是人工修正，知道低置信结果需要确认，也不能把现有题材头对人像的错误结果继续当成事实。

## 方案

沿用现有 CLIP + 风格锚图原型 + 题材线性头 + 影调规则，不引入新模型。Python 词典是服务端真源，前端保留一份显式契约并由回归脚本逐项比对。风格置信度继续使用锚图分数第一/第二名间隔在留一法上的分档校准，响应中把来源写成 `confidenceSource`；任何低于业务阈值的结果带 `needsReview=true`。

题材采用保守门控：只有非人像候选（`ARCHITECTURE`、`LANDSCAPE`、`STILL_FOOD`）达到高置信阈值时才返回题材；对疑似人像或置信不足的输入返回空题材，并在 `subjectGate` 中说明 `portraitEvidence`、`lowConfidence` 或 `nonPortraitOnly`。门控不改变模型原始分数，便于评估前后误判率。

前端不把人工编辑写回 `aiResult`。面板从 AI 原始结果渲染“AI 识别”，另维护本地 `humanEdits` 集合，增删后显示“人工修正”；重选图片、关闭弹窗或提交后清空编辑态。低置信提示使用“建议人工确认”，不把未达标数值包装成可靠百分比。

## 验证

新增脚本最多读取 30 张样本，支持文件名/目录编码的可选真值，输出标签分布、题材门控和混淆统计。性能部分分别测冷启动首张、热态单张和并发 4；缺少真实 20 张人像或服务未启动时，报告写明缺失项和“没做的验证”，不生成推测数字。

## 不做

- 不重训、不增加模型、不添加 npm 或 Python 依赖。
- 不改首页和螺旋墙的视觉布局，不改另一个会话负责的页面和样式文件。
- 不将人工修正伪装成模型输出，也不把画面外信息写进识别标签。
