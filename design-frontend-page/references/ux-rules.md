# UX rules → acceptance checklist

UI UX Pro Max 的 UX 规则要先按产品类型检索，再把返回规则逐条转成项目验收项。不要把下面的示例当成完整规则库，也不要编造规则编号；把检索到的原文或规则 ID 填入对应行。

## 检索卡

```text
产品类型：
目标用户：
首屏任务：
主风格 / 辅助风格：
色板 / 字体配对：
命中的 UX 规则 ID：
命中的 vue.csv 规范：
```

## 勾选项

- [ ] 首屏第一眼能看出产品、页面对象和主要任务。
- [ ] 主要操作只有一个明确的视觉优先级，按钮文案不会歧义或换行失控。
- [ ] loading、empty、error、disabled、focus-visible 都有可理解的状态。
- [ ] 表单错误靠近字段，说明如何修复，不只显示颜色。
- [ ] 键盘可以完成主要流程，焦点顺序和视觉顺序一致。
- [ ] 图片有替代文本；装饰图形不会进入阅读顺序。
- [ ] 正文、标签、占位符和状态文字的对比度符合项目目标。
- [ ] 内容变长、图片加载失败、候选为空时布局不塌陷。
- [ ] 移动端不依赖 hover；触控目标有足够尺寸和间距。
- [ ] 所有外部数据有来源标注；降级结果不冒充真接口结果。
- [ ] 每条检索到的 UX 规则都有“实现位置 + 验证方式 + 结果”。

## vue.csv 审查项

把 `vue.csv` 命中的规范附在代码审查记录里，至少检查：组件边界、props/emits 类型、异步 loading/error、key、可访问性、响应式 CSS、第三方依赖和构建体积。若项目不是 Vue，替换为对应栈的规范来源。
